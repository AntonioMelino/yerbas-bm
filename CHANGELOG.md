# CHANGELOG.md — Yerbas BM

## [2026-07-26] - Feature: admin-auth-jwt
- Rama: feature/admin-auth-jwt
- Qué se hizo: Implementada la autenticación del panel admin con JWT (único rol autenticado del sistema, sin registro de clientes — sección 10 de CONTEXTO.md). Se agregaron los DTOs (`LoginDto`, `LoginResponseDto`), las interfaces `IAuthService`/`IAdminUserRepository`/`ITokenGenerator`, el repositorio EF Core (`AdminUserRepository`), el generador de tokens (`JwtTokenGenerator`, HMAC-SHA256 vía `System.IdentityModel.Tokens.Jwt`) y el servicio de negocio (`AuthService`, valida contraseña con BCrypt). Se expuso `AuthController` con `POST /api/auth/login`. Las mutaciones de admin existentes (`POST`/`PUT`/`DELETE` de `CategoriesController` y `ProductsController`) quedaron protegidas con `[Authorize]`; los `GET` siguen públicos. Se agregó `AdminUserSeeder`, que crea el único admin la primera vez que la API arranca con `admin_users` vacía y `Seed:AdminUsername`/`Seed:AdminPassword` configurados (no hay endpoint de registro). Durante las pruebas se detectó y corrigió un bug: con `Jwt:Key` sin configurar, el middleware de autenticación rompía con 500 **cualquier** request (incluido `/api/health`, que no depende de la base) — se resolvió generando una clave de firma aleatoria efímera como fallback cuando no hay `Jwt:Key`, sin habilitar por eso el login (que sigue requiriendo una key real vía `JwtTokenGenerator`). Se verificó que el proyecto compila sin errores y, en runtime sin base de datos configurada, que `/api/health` responde 200, `/api/categories` (GET) sigue público, y `POST /api/categories` sin token devuelve 401 antes de tocar la base.
- Archivos principales afectados: `backend/YerbasBM.Application/DTOs/{LoginDto,LoginResponseDto}.cs`, `backend/YerbasBM.Application/Interfaces/{IAuthService,IAdminUserRepository,ITokenGenerator}.cs`, `backend/YerbasBM.Application/Services/AuthService.cs`, `backend/YerbasBM.Infrastructure/Repositories/AdminUserRepository.cs`, `backend/YerbasBM.Infrastructure/Services/JwtTokenGenerator.cs`, `backend/YerbasBM.Infrastructure/Data/AdminUserSeeder.cs`, `backend/YerbasBM.API/Controllers/AuthController.cs`, `backend/YerbasBM.API/Controllers/{CategoriesController,ProductsController}.cs`, `backend/YerbasBM.API/Program.cs`, `backend/YerbasBM.API/appsettings.json`, `backend/README.md`
- Post-review: tras `security-reviewer`/`code-reviewer`, se corrigieron un bug (login sin manejar cuando falta `Jwt:Key`, ahora capturado y devuelve 500 seguro) y un hallazgo de seguridad HIGH (`Jwt:Key` sin mínimo de longitud, ahora exige 32 bytes/256 bits), y se agregó un log `Warning` al arrancar cuando `Jwt:Key` no está configurado. Quedan como pendientes no bloqueantes (documentados en sección 11 de CONTEXTO.md): rate limiting en el login y un timing side-channel que permite enumerar el username.
- Autor: Claude

## [2026-07-25] - Feature: products-crud
- Rama: feature/products-crud
- Qué se hizo: Implementado el CRUD completo de Productos siguiendo el mismo patrón Clean Architecture que Categories. Se agregaron los DTOs (`ProductDto`, `CreateProductDto`, `UpdateProductDto`), las interfaces `IProductRepository`/`IProductService`, el repositorio EF Core (`ProductRepository`, con `Include(Category)` y filtro opcional por slug de categoría) y el servicio de negocio (`ProductService`). Se expuso `ProductsController` con `GET /api/products` (acepta `?category={slug}`), `GET /api/products/{id}`, `POST /api/products`, `PUT /api/products/{id}` y `DELETE /api/products/{id}`, tal como define la sección 6 de CONTEXTO.md. `GET /api/products` solo devuelve productos con `isActive=true` (soft hide). La subida de imagen a Supabase Storage queda pendiente de una feature aparte; por ahora `imageUrl` se recibe como texto plano en el DTO. Se verificó que el proyecto compila sin errores; la prueba funcional contra datos reales queda pendiente de una conexión a PostgreSQL/Supabase configurada localmente (mismo estado que la feature de categorías).
- Archivos principales afectados: `backend/YerbasBM.Application/DTOs/{ProductDto,CreateProductDto,UpdateProductDto}.cs`, `backend/YerbasBM.Application/Interfaces/{IProductRepository,IProductService}.cs`, `backend/YerbasBM.Application/Services/ProductService.cs`, `backend/YerbasBM.Infrastructure/Repositories/ProductRepository.cs`, `backend/YerbasBM.API/Controllers/ProductsController.cs`, `backend/YerbasBM.API/Program.cs`

## [2026-07-24] - Feature: categories-crud
- Rama: feature/categories-crud
